State Attributes & Activities

State Definition Language

Use a SQL-like CASE expression: STATE state FOR LEADING OBJECT TYPE 'Order' AS CASE ... END.

  • WHEN condition THEN 'State label' assigns a state.
  • ELSE 'State label' is optional, but useful for complete coverage.
  • Reference fields with event.type, event.attribute, or object.attribute.
  • Choose a different name after STATE for each attribute. Combine them later with Activity composition.
  • Values support CONCAT, COALESCE, ||, and nested CASE.
  • Quote spaced names like event."Stock After".
  • Use =, !=, <, <=, >, >=, LIKE, IS NULL, AND, OR, and parentheses.

Compose states and activities

Combine any saved event attributes. Change these expressions whenever you need a different view.

Example: CONCAT(event.state1, ' / ', event.state2). This defines episodes and transitions. Use event.combined_state for states only, or CONCAT(event.type, ' [', event.combined_state, ']') to include the original activity.
Expressions and missing values

Use CONCAT(...) or || to join values in any order, including literal text. Use CASE WHEN ... THEN ... ELSE ... END for conditional labels.

A missing value makes a concatenation missing. Use COALESCE(event.state2, 'Unknown') to include events without that state. Events with no combined state are excluded from state analyses. Every stateful event must have a nonempty activity label.

Named states retain their own leading object type and values. The analysis leading type controls pattern lifecycles. Outputs are exported as combined_state and state_activity.
